### Selected work

#### 01 — Nornes

**A contract-management intelligence platform built around a governed GraphRAG memory.**

Nornes ingests a project’s contract corpus — contracts, correspondence, instructions, and supporting documents — and connects it into a queryable knowledge graph. Teams can investigate the project through the graph rather than search a folder and hope the critical context was not missed.

Every useful answer should lead back to evidence: the original document, clause, page, and the relationships around it.

`Python` · `FastAPI` · `PostgreSQL` · `Neo4j` · `Next.js` · `TypeScript` · `GraphRAG`

| System | Purpose |
| --- | --- |
| Document ingestion | Reads, classifies, and indexes the contract corpus. |
| Knowledge graph | Connects documents, clauses, obligations, facts, and evidence. |
| Consolidation | Turns individual document processing into a coherent, queryable project memory. |
| Grounded tools | Supports graph-backed chat and specialised analysis for risks, timelines, finance, and obligations. |

The architecture is deliberately layered:

```text
foundation  →  structure  →  graphrag  →  agents
```

Each layer has one responsibility: run the platform, describe the project, build the graph, or work from its finished knowledge. That boundary keeps the system understandable as it grows.
